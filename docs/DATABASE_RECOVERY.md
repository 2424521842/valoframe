# 数据库恢复指南

瓦刻在数据库版本过新、SQLite 完整性检查失败、迁移备份失败或迁移无法原子提交时会停止启动。Windows 提示框中的“是”会打开应用数据目录；程序不会自动删除或覆盖可疑数据库。

## 自动保护

- 数据库文件名为 `highlight-index.sqlite3`。
- 从旧 schema 升级前，应用通过 SQLite Online Backup API 生成包含 WAL 最新提交的独立备份。
- 备份位于同级 `backups` 目录，命名为 `highlight-index.pre-v*-to-v*-*.sqlite3`，只保留最近 3 份。
- 备份写入临时文件后必须通过 `quick_check` 和 `foreign_key_check`，验证成功才会发布为 `.sqlite3`。
- schema 迁移和 `user_version` 更新在同一个 `BEGIN IMMEDIATE` 事务中；失败会整体回滚。
- 升级到 schema v13 时，旧版本永久删除 intent 因缺少“移入回收站时”的身份依据会被安全失效；旧回收站条目也不会被补造授权。若永久删除提示缺少身份快照，请先恢复该素材，再重新移入回收站并二次确认。

## 恢复前先判断错误

- 如果提示数据库版本高于当前应用支持版本，不要用旧程序覆盖它。应安装创建该数据库的同版本或更高版本。
- 如果提示完整性、外键或迁移错误，先退出瓦刻并保留错误原文、当前数据库、`-wal`/`-shm` 伴随文件和整个 `backups` 目录。
- 迁移备份只代表升级前的状态，恢复它可能丢失备份生成后的标签、备注、回收状态和扫描结果；原视频不会因数据库恢复被删除。

## 人工恢复步骤

1. 确认任务管理器中没有 `valorant-highlight-manager.exe` 进程。
2. 把整个应用数据目录复制到另一个位置；不要只复制主 `.sqlite3` 而遗漏可能存在的 `-wal` 和 `-shm`。
3. 在应用数据目录中新建一个明确命名的隔离目录，把当前 `highlight-index.sqlite3` 及同名前缀的 `-wal`、`-shm` 移入隔离目录。不要删除它们。
4. 从 `backups` 选择时间最新且版本合适的备份，复制一份并命名为 `highlight-index.sqlite3`；不要直接移动或改写原备份。
5. 启动当前最新版瓦刻，让它对恢复副本执行正常的健康检查和向前迁移。确认来源、标签、备注和回收站后，再保留或归档隔离副本。
6. 若仍失败，立即退出，并恢复第 2 步的完整目录副本；不要连续尝试多个覆盖操作。

公开发布前应在干净 Windows 虚拟机上分别演练旧库升级、未来版本拒绝、损坏库拒绝、从备份恢复和恢复后的再次升级，并保存输入数据库与验收记录。
