# 瓦刻（VALOFRAME）v0.2.5 版本计划书

> 文档状态：实施计划
>
> 编制日期：2026-08-27
>
> 目标平台：Windows 10/11 x64
>
> 目标版本：`v0.2.5`
>
> 版本基线：`v0.2.4`、SQLite schema v21、Tauri 2 + Rust + React 19 + TypeScript
>
> 目标 schema：继续使用 v21，本版本不新增数据库迁移

## 1. 版本定位

v0.2.5 定位为“显示可读性与任务反馈优化版本”。本版本不扩大素材来源或文件删除权限，也不为广告引入第三方 SDK、外域脚本或新的 WebView capability；版本集中处理五个直接影响使用体验或产品配置边界的问题：缩略图生成完成后不能及时显示、界面字体偏小、扫描进度在数据真正导入完成前过早显示 100%、NVIDIA 待录入窗口在较小屏幕或较大字体下无法看到“录入到素材库”按钮，以及广告开关与接口等运营配置不应暴露在普通用户设置中。

本版本的核心原则是：后台状态必须及时反映到界面；进度信息不得让用户误以为任务已结束；字体调整后关键内容和操作仍然可见、可滚动、可通过键盘访问。

## 3. 产品目标与成功标准

### 3.1 产品目标

1. 缩略图在后台生成完成后自动替换占位图，不要求刷新页面、切换筛选或重新进入素材库。
2. 默认字体比 v0.2.4 更易阅读，并允许用户在设置中选择“标准”“大号”或“特大”。
3. 扫描文件达到 100% 后，界面明确进入“正在导入数据”或“正在完成收尾”阶段，不再把仍在运行的任务显示为已完成。
4. NVIDIA 手动录入窗口在最小支持窗口、系统显示缩放和“特大”字体下仍能滚动到“录入到素材库”按钮。
5. 普通用户不再看到或修改“显示广告”、广告素材接口和落地域名配置；广告活动由维护者后台启停和配置。

### 3.2 成功标准

- 已生成缩略图的 `ready` 状态到达后，当前列表卡片和已打开详情均能局部更新，不触发整页刷新或分页重载。
- 首次打开素材库时，即使缩略图任务在事件监听建立前后快速完成，也不会长期停留在占位图。
- 字体设置即时作用于全部工作区，重启应用后保持；恢复默认设置后回到“标准”。
- 新的默认“标准”字号整体高于 v0.2.4；“大号”和“特大”继续按稳定比例放大，而不是只放大设置页或正文。
- 扫描、导入、元数据处理和收尾期间均显示与实际阶段一致的文案；非终态不得显示 100%。
- 完成、部分完成、取消和失败仍保持现有终态语义，不因进度显示优化而丢失扫描摘要、重复通知或错误刷新索引。
- 在应用最小窗口 `760 × 560`、常用窗口 `1280 × 820` 和 Windows 125%/150% 显示缩放下，NVIDIA 录入弹窗都能正常滚动和提交。
- 设置页、恢复默认文案和本机偏好载荷不再把广告启停、接口或允许域名作为用户偏好；旧版本保存的相关值不能继续控制 v0.2.5 的广告行为。
- 后台未配置、明确停用、返回空活动或返回非法配置时，客户端不显示广告并安全降级；广告位若展示，仍必须保留清晰的“广告”标识。

## 4. 功能规格

### 4.1 缩略图及时显示

#### 问题

部分素材的缩略图已经在后台生成完成，但卡片仍长时间显示占位图，直到用户刷新页面或触发其他列表更新。当前已完成一版初步修复，v0.2.5 需要把该修复收敛为稳定行为并防止竞态回归。

#### 实施要求

- 保留“按当前页批量确保缩略图”的策略，不让虚拟列表卡片挂载产生大量重复命令。
- `thumbnail-progress` 到达 `ready` 时，只更新对应素材的状态、revision 和媒体 URL；不得重新请求整个素材列表。
- 处理“任务完成早于前端监听建立”“同一 revision 重复通知”“缓存淘汰后以同一素材重新生成”和“来源自带封面被 suppressed”四类边界。
- 缩略图失败、生成器不可用或媒体格式不支持时继续显示稳定回退图，不进入自动重试死循环。
- 现有初步修复在合并前必须通过自动化回归和 Windows 实机验证；未经验证不得仅以“本机看起来正常”关闭该工作项。

#### 验收场景

- 新扫描素材进入当前页后，缩略图生成完成即可自动出现。
- 快速生成与慢速生成均能更新，且每个有效 revision 只应用一次。
- 切换分页、筛选、网格/列表视图后不出现旧缩略图覆盖新缩略图。
- 图片加载失败后显示回退图；新的 revision 到达时可以再次尝试显示。
- 更新单张缩略图时，列表、facets、来源和标签请求次数不增加。

### 4.2 全局字体增大与字体大小设置

#### 设置项

在“设置与关于 → 常规”中新增“字体大小”选项：

| 选项 | 建议缩放 | 说明 |
| --- | ---: | --- |
| 标准 | 100% | v0.2.5 新默认值；基础字号较 v0.2.4 增大一级 |
| 大号 | 112.5% | 适合高分辨率屏幕或需要更清晰文字的用户 |
| 特大 | 125% | 优先保证可读性，允许局部区域通过滚动容纳内容 |

最终像素值可在实现阶段根据视觉回归微调，但三个档位的相对顺序、即时生效和持久化行为不得改变。

#### 实施要求

- 在 `AppPreferencesV1` 中增加经过白名单校验的字体档位字段；旧版设置缺少该字段时使用“标准”，不得清空其他已有偏好。
- 设置变化即时写入应用根节点的稳定属性或 CSS 变量，重启应用后恢复用户选择。
- 建立统一的排版变量，逐步替换主要用户可见区域中分散的固定小字号，避免只改变根字号但大量 `px` 文本完全不随设置变化。
- 标题、正文、说明、表单标签、按钮、状态文字和错误提示都应响应字体档位；纯装饰图形和无需放大的媒体画面不跟随缩放。
- 同步检查行高、按钮最小高度、输入框、下拉菜单、卡片、表格和弹窗，不得通过裁切、隐藏文字或禁止换行来维持旧布局。
- “恢复默认设置”的确认文案和行为包含字体大小，并把该项恢复为“标准”。

#### 验收场景

- 三个档位可通过鼠标和键盘选择，设置后无需重启即可看到变化。
- 重启后保留选择；非法或未知持久化值安全回退到“标准”。
- 从 v0.2.4 升级时保留启动位置、素材库视图、排序、播放、动效和更新等既有偏好。
- 素材库、扫描、预览、快速挑片、标签管理、设置和全部主要弹窗均响应字体变化。
- 在最小支持窗口和“特大”字号下，关键按钮仍可见或可通过明确的滚动区域到达；焦点样式不被裁切。

### 4.3 扫描进度分阶段显示

#### 问题

当前进度主要由“已扫描文件数 / 预计文件数”计算。文件枚举完成时该比值会达到 100%，但后端仍可能在导入索引、写入元数据和完成事务收尾。用户看到 100% 后长时间没有结束反馈，容易误以为应用卡住。

#### 进度语义

扫描界面使用“阶段 + 总体进度”表达任务，不用虚构精确的数据库写入速度：

| 阶段 | 建议总体区间 | 显示文案 | 进度行为 |
| --- | ---: | --- | --- |
| 启动/发现来源 | 0%–10% | 正在准备扫描 / 正在发现来源 | 无可靠总量时使用忙碌动画 |
| 扫描文件 | 10%–85% | 正在扫描录像 · 已处理 X / Y | 使用现有 processed/total 映射，最高不超过 85% |
| 导入数据 | 85%–95% | 扫描完成，正在导入数据 | 有可靠计数时递增，否则显示阶段忙碌动画 |
| 元数据与收尾 | 95%–99% | 正在整理元数据 / 正在完成收尾 | 非终态最高只能显示 99% |
| 成功完成 | 100% | 扫描完成 | 仅 `completed` 终态显示 100% |

百分比区间是界面呈现规则，不改变后端对真实文件数、任务摘要和终态的记录。若某类扫描无法提供完整阶段事件，应优先显示阶段名称和不确定进度动画，不能伪造连续增长。

#### 实施要求

- 后端在文件枚举结束、开始写入索引、开始元数据处理和最终提交前发出可区分的 phase/message；事件仍绑定同一 job ID，并保持 processed 单调不回退。
- 前端把进度计算抽成可单测的纯函数，统一处理 determinate、indeterminate、cancelling 和 terminal 状态。
- 所有非终态进度上限为 99%；只有 `status = completed` 且 `terminal = true` 时显示 100%。
- `partial`、`cancelled` 和 `failed` 不伪装成 100% 成功；进度条停止后由现有终态摘要明确说明结果。
- 取消发生在导入或收尾阶段时继续使用后端现有安全取消语义，界面显示“正在完成安全取消”，不得立即清空任务或允许启动并发扫描。
- `aria-valuenow`、可访问名称和状态播报与视觉阶段一致；不确定进度不提供虚假的数值。

#### 验收场景

- 扫描计数达到 X/X 后，界面转为“正在导入数据”，且百分比仍小于 100%。
- 导入耗时较长时动画持续运行，窗口仍可操作，取消按钮状态正确。
- 终态事件到达后只显示一次 100% 和完成摘要，不重复刷新列表。
- 任务在导入阶段失败、取消或部分完成时显示真实结果，不短暂闪现“100% 扫描完成”。
- 应用重启后接管仍在运行或已终结的任务时，阶段和终态能够从持久状态恢复。

### 4.4 NVIDIA 手动录入弹窗滚动

#### 问题

加入视频预览后，NVIDIA 手动录入弹窗的总高度可能超过可用视口。较小窗口、较高系统缩放或增大字体时，底部“录入到素材库”按钮会落到窗口之外，导致用户无法完成录入。

#### 实施要求

- 弹窗设置基于视口的最大高度，内容超出时在弹窗内部形成明确的纵向滚动区域。
- 鼠标滚轮、触控板、Page Up/Page Down、Home/End 和键盘焦点移动均能到达底部操作区。
- 优先让标题与底部操作区保持稳定，预览和表单作为中间滚动内容；若沿用整窗滚动，也必须确保提交按钮可见、可聚焦且不会被窗口边缘遮挡。
- 底部操作区在滚动容器内使用与背景一致的遮挡层和分隔线，避免表单文字透出；不得因 `overflow` 裁切下拉菜单浮层。
- 视频区域允许在低高度视口下适度收缩，但不能通过隐藏表单、提交按钮或错误信息解决高度问题。
- 字段校验失败后，应把第一个错误字段滚动到可见区域，并保持提交错误提示可读。

#### 验收场景

- 在 `760 × 560` 窗口中打开带预览的录入弹窗，可以使用滚轮滚动到底部并点击“录入到素材库”。
- “标准”“大号”“特大”三个字体档位下均能完成同一流程。
- 新建账户导致表单额外增加字段时，操作区仍可到达。
- 下拉选择英雄、地图和模式时，选项不被弹窗滚动容器裁切。
- 提交中按钮显示“正在录入…”，且滚动不会导致重复提交或意外关闭弹窗。

### 4.5 移除用户设置中的广告控制

#### 问题

v0.2.4 把“显示广告”开关、广告素材接口和允许打开的落地域名放在普通设置页。这些内容属于应用维护与投放运营配置，不应要求普通用户理解、填写或维护，也不应允许任意本机偏好把客户端指向未经维护者配置的广告接口。

#### 用户界面调整

- 从“设置与关于 → 常规”中移除“显示广告”开关。
- 同时移除“广告素材接口”和“允许打开的广告域名”等关联输入项，不保留隐藏的高级入口或快捷键入口。
- 更新“恢复默认设置”的说明，不再把广告配置列为可恢复的用户偏好。
- 广告卡片真正展示时继续显示明确的“广告”标识；本工作项只隐藏运营配置，不隐藏内容的广告属性。

#### 后台控制要求

- 广告展示与否、有效期、素材和落地策略改由维护者后台统一配置；客户端只消费应用预先信任的固定配置入口，不接受用户输入的任意接口地址。
- 后台可通过停用活动或返回空的有效素材列表停止展示，无需用户修改设置或重新安装应用。
- 素材接口地址和落地域名信任边界应来自安装包内置配置或经过验证的维护后台配置，不得相信广告素材自带的任意允许列表。
- 后台配置缺失、超时、签名或格式校验失败时 fail closed：不展示广告、不打开未知链接，也不影响素材库、扫描和预览功能。
- 保留现有安全边界：不引入第三方脚本、SDK、iframe 或视频广告；界面不直连外域；素材继续由 Rust 后端校验并缓存；点击链接必须为 HTTPS 且通过允许域名校验。
- 后台控制不得新增账号、游戏、文件路径、设备标识等数据上传。既有一次性点击标识和广告位标识如继续使用，应在隐私说明中明确。

#### 旧版本兼容

- v0.2.5 读取 v0.2.4 的本机偏好时，忽略并清除 `adsEnabled`、`adManifestEndpoint` 和 `adAllowedHosts`，同时保留其他启动、素材库、播放、动效和更新偏好。
- 移除广告用户偏好不需要 SQLite schema 迁移；广告素材、展示与点击日志表若继续由后台链路使用，保持现有 schema v21 数据结构和清理规则。
- 旧版曾填写的自定义广告接口在升级后不得继续发起请求，避免隐藏设置在用户不可见时仍然生效。

#### 验收场景

- 设置页不存在“显示广告”“广告素材接口”或“允许打开的广告域名”控件，也无法通过键盘焦点访问已隐藏元素。
- 从带有旧广告偏好的 v0.2.4 升级后，其他设置保持不变，旧广告接口不再被请求。
- 维护后台启用有效活动时，广告卡按既有安全协议显示并带“广告”标识；停用或清空活动后广告卡消失。
- 后台离线、超时、返回非法素材或未知落地域名时，客户端不显示对应广告、不打开链接且不出现全局错误弹窗。
- 浏览器预览和正式 Tauri 环境均不会因为缺少后台广告配置而影响应用启动。

## 5. 技术方案与改动面

### 5.1 前端设置与排版

预计涉及：

- `src/lib/appPreferences.ts`：增加字体档位类型、默认值、读取和 patch 校验。
- `src/hooks/useAppPreferences.ts`：沿用现有即时保存与恢复默认流程。
- `src/App.tsx`：把字体档位映射到根节点属性或 CSS 变量，并负责卸载清理。
- `src/screens/SettingsWorkspace.tsx`：在“常规”中增加字体大小选择，并删除广告开关、素材接口和允许域名控件。
- `src/cinematic.css` 与通用 UI 样式：建立排版变量，修正放大后的换行、控件高度、弹窗和滚动布局。

字体偏好是本机界面设置，不写入 SQLite。本版本继续使用数据库 schema v21；现有偏好载荷缺少新字段时按默认值补齐，不要求用户重置设置。广告控制字段从本机用户偏好中移除，升级时只丢弃这三个旧字段，其他偏好必须保留。

### 5.2 扫描进度契约

预计涉及：

- `src-tauri/src/commands.rs` 及扫描模块：补充导入和收尾阶段事件，保持 job ID、单调进度和终态唯一性。
- `src/types.ts`：收紧前端已知 phase 的类型和展示映射，同时保留对未知 phase 的安全回退。
- `src/hooks/useScanController.ts`：保持任务接管、取消和终态结算逻辑，避免重复通知。
- `src/screens/ScanWorkspace.tsx`：使用统一的阶段展示函数，不再直接把 processed/total 映射到 100%。

### 5.3 缩略图与手动录入

预计涉及：

## 8. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 大量固定 `px` 字号不响应根字号 | 设置看似生效但界面不一致 | 建立排版变量并用视觉回归覆盖全部主要工作区 |
| 字体放大导致卡片、表格和弹窗溢出 | 文字或按钮不可见 | 允许合理换行和内部滚动，以最小窗口 + 特大字号作为强制验收组合 |
| 加权进度被误认为真实处理比例 | 用户仍对进度产生错误预期 | 同时显示明确阶段文案；无可靠计数时使用忙碌动画，不伪造精确速度 |
| 新 phase 破坏旧的任务接管或取消流程 | 重复终态、无法取消或摘要丢失 | 保持 job ID 和终态协议不变，只扩展非终态阶段，并补恢复测试 |
| 弹窗 `overflow` 裁切下拉浮层 | 无法选择分类信息 | 确认下拉内容使用 portal；自动化与实机检查每个下拉框 |
| 缩略图监听竞态仍有遗漏 | 偶发需要刷新 | 覆盖监听前后快速完成场景，并以数据库/当前页状态校验作为稳定补偿机制 |
| 移除开关后后台误配置会直接影响全部用户 | 错误广告或未知链接无法由用户侧关闭 | 后台分环境发布、固定可信入口、严格校验、紧急停用能力和 fail-closed 客户端策略 |
| v0.2.4 隐藏广告偏好继续生效 | 用户无法看到或纠正旧接口请求 | 升级时显式忽略并清理旧字段，测试确认不再访问旧 endpoint |

## 9. 完成定义

v0.2.5 被视为“功能完成”需同时满足：

- 五个工作项的验收场景全部通过，缩略图初步修复已有自动化和实机证据。
- 默认字体确实增大，用户可在设置中即时切换并持久化三个档位。
- 任何仍在运行的扫描任务都不会显示 100%；导入和收尾阶段具有清晰反馈。
- NVIDIA 录入弹窗在最小窗口、150% 系统缩放和“特大”字体下仍可滚动并完成提交。
- 设置页不再出现任何广告启停或接口配置；广告可由维护者后台启停，且后台异常时安全不展示。
- v0.2.4 遗留广告设置已失效并被清理，其他本机偏好保持不变；广告内容仍有清晰的“广告”标识。
- 数据库继续使用 schema v21；升级只清理旧广告控制字段，不清空其他应用偏好，也不改变原视频的只读与删除授权边界。
- 全部工程门禁、Windows 实机矩阵和 v0.2.4 → v0.2.5 更新验证通过。

功能完成不等于稳定发布完成。只有版本号、签名更新包、安装器、发布说明、SHA-256、对应源码与仓库现行稳定发布门禁全部一致后，才能发布 `v0.2.5` 稳定版。
