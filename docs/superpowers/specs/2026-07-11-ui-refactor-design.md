# 无畏高光管理器 UI 重构设计

日期：2026-07-11

## 1. 背景

当前应用已具备素材扫描、账号与对局分组、搜索筛选、视频预览、收藏、标签、备注和文件定位等核心能力，但主工作台存在以下体验问题：

- 信息密度高但层级不够清晰，用户需要在多个区域来回确认筛选与对局信息。
- 筛选后仅展示空结果，未明确说明哪些条件隐藏了素材。
- 右侧详情面板与中间工作区关联感较弱。
- 固定最小宽度导致约 1024px 窗口出现横向裁切。
- 品牌红使用面积较大，长时间浏览时视觉负担偏高。
- 部分控件只有视觉形态，没有清晰的可用状态或实际作用。

本次重构采用渐进式结构调整：保留后端接口、数据模型和现有业务状态，集中重构 React 展示层、交互层与响应式布局。

## 2. 已确认的方向

- 重构深度：完整 UI 重构。
- 视觉方向：A「沉浸战术台」。
- 布局方向：A「自适应三栏」。
- 核心目标：同时提升素材定位效率与高光浏览沉浸感。
- 交互范围：允许新增不依赖后端的纯前端交互。
- 实施方式：渐进式结构重构并建立轻量设计系统。

## 3. 目标与成功标准

### 3.1 目标

1. 用户能快速理解当前素材范围、活动筛选条件和无结果原因。
2. 对局信息与高光封面成为中间工作区的视觉核心。
3. 宽屏保留三栏高效率布局，窄窗口不再横向裁切。
4. 扫描、预览、整理和文件定位功能保持完整。
5. UI 组件职责更聚焦，避免继续扩大 `App.tsx` 与单一 CSS 文件的复杂度。

### 3.2 可验证标准

- 工作区展示“当前可见数量 / 素材总数”。
- 所有活动筛选条件都能看见、单项清除并一键全部清除。
- 空状态能区分素材库为空、加载失败和筛选后无结果。
- 约 1024px 宽度下没有页面级横向滚动或被裁切的主要操作。
- 宽屏固定显示详情面板；中等与窄窗口使用详情抽屉。
- 扫描、收藏、标签、备注、复制路径、打开原位置和视频预览仍可用。
- 现有前端测试通过，并为新增状态与响应式行为补充测试。

## 4. 范围

### 4.1 本次包含

- 应用顶部栏、侧栏、工作区工具栏、对局分组、高光卡片和详情面板的视觉与结构调整。
- 设计变量：颜色、间距、字体、圆角、边框、阴影、层级和动效。
- 活动筛选标签、结果数量、筛选清除和高级筛选展开。
- 自适应三栏、详情抽屉和可折叠侧栏。
- 加载、扫描、错误、空状态、文件丢失和媒体不可用状态。
- 键盘焦点、对比度、可点击面积和减少动画偏好。
- 与新交互相关的前端纯函数和组件测试。

### 4.2 本次不包含

- Rust command、SQLite schema、扫描与元数据采集逻辑变更。
- 批量标签、批量收藏或批量文件操作。
- 视频自动播放、悬停自动播放或视频编辑能力。
- 完整通用组件库或第三方 UI 框架迁移。
- 击杀事件时间线或逐条击杀事件列表展示；后端已有事件数据保持不变。
- 原始素材的移动、删除、重命名或修改。

## 5. 信息架构与布局

### 5.1 顶部应用栏

顶部栏保持紧凑，包含品牌标识、当前工作区名称、素材统计、扫描状态与主要扫描操作。移除无实际功能的伪窗口操作、“视频管理”和“设置”等未实现入口；这些入口不属于本次重构范围。

### 5.2 左侧导航

左栏按以下顺序组织：

1. 快捷视图：全部素材、今日、收藏、文件丢失。
2. 账号：全部账号与各账号计数。
3. 来源目录：来源名称、素材计数与可用状态。
4. 扫描状态：最近扫描摘要、当前进度、重新扫描和添加目录。

账号和来源使用独立滚动区域，扫描状态固定在底部。窄窗口下左栏可折叠为导航抽屉。

### 5.3 中间工作区

中间区域从上到下包括：

1. 工作区标题与“当前可见数量 / 总数”。
2. 主搜索框、扫描按钮和高级筛选开关。
3. 常用筛选与排序。
4. 活动筛选标签及一键清空。
5. 扫描或加载的非阻塞状态提示。
6. 账号与对局分组时间线。
7. 高光卡片网格或解释性空状态。

### 5.4 右侧详情

详情面板按任务优先级组织：

1. 标题、收藏状态和关闭按钮（抽屉模式）。
2. 16:9 视频预览或文件不可用状态。
3. 胜负、比分、KDA、英雄、地图、模式、战斗分和击杀数。
4. 标签与备注。
5. 可折叠的文件与元数据详情。
6. 固定在底部的打开原位置、复制路径等操作。

### 5.5 响应式规则

- 宽度不低于 1180px：左栏、中间工作区和右侧详情固定三栏显示。
- 宽度为 900–1179px：左栏保留，右侧详情变为覆盖式抽屉。
- 宽度低于 900px：左栏与详情均为抽屉，中间工作区占满可用宽度。
- 页面不得依赖固定的 1180px 最小宽度。

## 6. 视觉系统

### 6.1 色彩

- 页面背景：深海军蓝与炭黑层级。
- 主文本：高对比冷白；次级文本使用清晰但不过暗的灰蓝。
- 品牌红：主要操作、选中状态、关键焦点和少量品牌装饰。
- 胜利状态：青绿色，并配合文字或图标。
- 失败与错误：红色，并通过文字说明，不能只依赖颜色。
- 普通卡片和边界使用中性色，避免全界面红色描边。

### 6.2 字体与数字

正文使用系统中文无衬线字体。比分、KDA、时长和战斗分使用等宽数字或等宽数字特性，保证纵向比较稳定。标题层级保持克制，不使用过多大号文字。

### 6.3 卡片与动效

高光卡片采用 16:9 封面。时长、收藏、标签和文件状态放在封面边缘或卡片底部，不遮挡主要画面。悬停只做轻微位移、描边和信息强化，不自动播放视频。动效尊重 `prefers-reduced-motion`。

## 7. 核心交互

### 7.1 搜索与筛选

- 主搜索输入保持即时过滤，并继续使用延迟值避免大列表输入卡顿。
- 常用筛选直接显示；高级筛选可展开收起。
- 活动筛选统一映射为可关闭标签。
- 单击标签关闭按钮只清除对应条件。
- “清除全部”恢复全部素材视图，但不改变排序，避免意外打乱浏览顺序。
- 切换快捷视图时保留搜索与其他筛选，并通过活动标签明确显示叠加条件。

### 7.2 素材选择与详情

- 点击卡片更新 `selectedClipId`。
- 宽屏直接更新固定详情面板。
- 中等与窄窗口同时打开详情抽屉。
- 关闭抽屉不清空素材选择，重新打开时保持上下文。
- 按 `Escape` 关闭当前抽屉，焦点返回触发它的素材卡片。

### 7.3 对局与卡片

- 对局头部优先展示胜负、比分、KDA、英雄、地图、模式和时间。
- 缺少结构化字段时使用稳定的“未知”或文件时间兜底，不生成虚假数据。
- 卡片主要展示封面、高光标题、时长、标签、收藏和文件状态。
- 文件名与大小降为次要信息，完整内容在详情面板中展示。

### 7.4 扫描与状态

- 扫描进度持续显示在侧栏，并在工作区提供紧凑状态条。
- 扫描期间素材浏览保持可用，扫描按钮显示忙碌状态并禁止重复触发。
- 扫描完成后展示新增、更新、丢失和元数据警告摘要。
- 诊断信息保留复制能力，但默认折叠，避免挤占工作区。

## 8. 状态与数据流

`App` 继续拥有现有加载、扫描、筛选、标签和选中状态。新增的展示状态只包括：

- 高级筛选是否展开。
- 左侧导航抽屉是否打开。
- 详情抽屉是否打开。

本次重构只提供一套经过响应式适配的卡片密度，不增加密度切换状态。

活动筛选标签由现有筛选状态派生，不建立第二份筛选状态。每个标签包含稳定键、用户可读标签和清除回调。可见数量直接使用 `visibleClips.length`，总数使用 `clips.length`。

现有数据流保持不变：

1. 前端通过现有 API 加载素材与标签。
2. 现有纯函数执行筛选、排序和账号/对局分组。
3. 用户选择卡片后，详情面板按现有 API 获取媒体信息。
4. 收藏、标签和备注更新继续合并回本地素材列表。

## 9. 异常与空状态

- 列表加载失败：在中间工作区展示错误与重试入口。
- 扫描失败：保留已有索引，侧栏和状态条显示错误摘要。
- 媒体不可用：预览区显示原因；丢失文件提供重新扫描、复制路径和查看最近已知路径。
- 备注或标签保存失败：错误留在对应编辑区域，并保留用户输入。
- 素材库为空：引导扫描默认目录或添加目录。
- 筛选后无结果：列出活动条件，并提供清除单项或全部条件的入口。
- 未选择素材：详情区显示简洁提示，不渲染伪数据。

## 10. 组件边界

目标组件结构如下：

- `AppShell`：顶层响应式布局和抽屉开关。
- `AppTopBar`：品牌、统计、扫描状态和主要操作。
- `SourceSidebar`：快捷视图、账号、来源和扫描卡片。
- `WorkspaceHeader`：标题、结果统计和主操作。
- `FilterToolbar`：搜索、常用筛选、高级筛选与排序。
- `ActiveFilterChips`：派生筛选标签和清除操作。
- `ClipGrid`：账号/对局分组、素材卡片和空状态。
- `ClipCard`：单个素材的封面与摘要交互。
- `DetailPanel`：详情区域骨架。
- `VideoPreview`、`MatchSummary`、`TagEditor`、`NoteEditor`：详情内部职责单一的子组件。
- `StatusBanner` 与 `ScanDiagnostics`：加载、扫描和诊断反馈。

不会为了本次重构抽象与业务无关的通用组件。只有至少在两个位置复用、且交互一致的视觉元素才提取为基础组件。

## 11. 兼容现有改动

当前工作区存在尚未提交的前后端改动，包括扫描进度、对局元数据和详情展示。本次实现必须以这些文件的当前内容为基线：

- 不重置、不覆盖用户现有改动。
- 先补测试描述目标行为，再逐步移动或修改展示代码。
- 业务逻辑与视觉重构分步完成，避免一次性替换整个 `App.tsx`。
- 每次修改前检查相邻差异，确保重构没有删除新字段和扫描状态。

## 12. 测试与验收

### 12.1 自动化测试

- 活动筛选标签的生成、单项清除和全部清除。
- 结果计数使用可见数量与总数量。
- 搜索与快捷视图叠加时的空状态说明。
- 详情抽屉开关不清空选中素材。
- 文件丢失状态展示恢复导向。
- 现有账号分组、筛选、详情与扫描状态测试继续通过；当前要求渲染击杀事件时间线的详情测试改为验证击杀数汇总与无事件列表。
- 执行 `npm test` 与 `npm run build`。

### 12.2 手动验证

- 约 1024、1280 和 1600px 窗口宽度。
- 有素材、无素材、筛选无结果、文件丢失和扫描错误场景。
- 视频可播放与不可播放场景。
- 键盘顺序、可见焦点、`Escape` 关闭抽屉和焦点返回。
- 深色界面对比度、长文本截断与中文标签换行。
- Tauri 窗口内实际视频预览、复制路径和打开原位置。

## 13. 实施风险与对策

- 风险：`App.tsx` 状态集中，重排时容易引入业务回归。对策：保留状态所有权，先提取纯展示组件，再调整布局。
- 风险：单一 `App.css` 继续膨胀。对策：先建立变量和明确区段；当组件样式独立且稳定时再拆分文件。
- 风险：响应式抽屉增加焦点管理复杂度。对策：使用原生按钮、明确的关闭操作、`Escape` 处理和焦点返回测试。
- 风险：品牌红过度使用影响可读性。对策：红色仅用于强调，普通边界和表面保持中性。
- 风险：真实封面缺失导致视觉效果不稳定。对策：保留确定性的色调占位封面，并保证文字对比度。

## 14. 完成定义

当以下条件全部满足时，本次 UI 重构完成：

1. 已确认的信息架构、沉浸战术台视觉和自适应三栏布局落地。
2. 新增筛选反馈、结果计数、解释性空状态和响应式详情抽屉。
3. 详情面板不渲染击杀事件时间线或逐条事件列表。
4. 除已明确移除的击杀事件时间线外，现有核心功能未丢失，前端测试与构建通过。
5. 1024、1280、1600px 窗口手动检查通过。
6. 未修改后端协议或原始素材只读边界。
