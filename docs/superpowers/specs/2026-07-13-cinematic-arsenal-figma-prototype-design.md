# 无畏时刻管理器：电影兵器库 Figma 原型设计

日期：2026-07-13

## 1. 目标

为无畏时刻管理器制作一套可点击的桌面端 Figma 高保真原型，用于在进入 React UI 重构前验证信息架构、视觉系统和核心交互。

首版原型覆盖三个核心页面：

1. 扫描目录
2. 素材库 / 对局分组
3. 素材预览

原型必须能够串起“扫描目录 → 浏览素材 → 预览与标记”的主流程，并与现有 Tauri 2 + React 19 应用中的扫描、筛选、账号分组、对局分组、收藏、标签、备注和打开原位置能力建立明确映射。

## 2. 设计方向

采用“电影兵器库”方向。视频缩略图和预览画面是界面的视觉中心，扫描、筛选和元数据区域保持克制、清晰。

视觉语言受无畏契约启发，但不直接复制官方客户端组件、Logo、角色立绘或其他受保护素材。设计通过黑红配色、锐利几何、战术分区和电影化媒体表现形成原创产品界面。

### 2.1 颜色

- 应用背景：近黑色 `#07080B`
- 一级面板：`#111319`
- 二级面板：`#181A21`
- 主强调色：无畏红 `#FF4655`
- 深红交互色：用于悬停、按下和环境光，不大面积铺满
- 主文字：暖白 `#ECE8E1`
- 次要文字：低对比灰白
- 收藏：少量金色
- 成功：低饱和绿色
- 警告和文件缺失：红橙色，与主操作红保持可辨识差异

### 2.2 材质与形状

- 视频封面和播放器叠加暗红渐变、轻微胶片颗粒与局部聚光。
- 导航选中项、主按钮、胜负状态和时间轴标记使用锐角切面。
- 普通信息面板使用克制的小圆角、细边界和轻量阴影，避免所有区域都采用尖角。
- 红色环境光只用于建立媒体区的空间层次，不降低文字和控件对比度。

### 2.3 字体与数据排版

- 中文沿用项目当前的系统中文字体方向，优先匹配 `Microsoft YaHei UI` / `Microsoft YaHei`。
- Figma 环境不可用时，选择可用的中文无衬线字体作为原型替代，并在 Foundations 页记录映射关系。
- 标题提高字重并适度增加字距。
- 比分、时长、KDA 和容量等数据使用紧凑、对齐稳定的数字排版。

## 3. 页面结构

三个页面共用统一应用框架：顶部品牌与状态栏、左侧主导航、中央工作区。首版主画板尺寸为 1440×900。

### 3.1 扫描目录

页面目标是让首次使用者快速理解扫描范围、识别账号并开始建立本地素材索引。

主要区域：

- 顶部标题、说明和扫描状态
- 扫描目录列表
- 添加目录入口
- 已识别账号列表
- 上次扫描统计
- 扫描进度和完成状态
- 红色“开始扫描”主按钮

“开始扫描”是页面唯一的强主操作。扫描完成后，用户可直接进入素材库。

### 3.2 素材库 / 对局分组

页面目标是通过账号和对局分组快速定位高光素材，同时让视频缩略图保持最高视觉权重。

主要区域：

- 顶部全局搜索
- 账号、英雄、地图、模式、日期、收藏和排序筛选
- 账号分组标题
- 对局摘要：地图、模式、胜负、比分、KDA、片段数
- 电影胶片式横向素材卡片
- 收藏、时长、容量和文件状态

对局数据是辅助信息，不能压过视频封面。账号和对局分组支持展开与收起。

### 3.3 素材预览

页面目标是高质量预览片段、定位关键时间点，并完成标签与备注整理。

采用三栏剧院式布局：

- 左侧：当前对局的片段列表
- 中间：大幅视频播放器、控制条、时间轴和事件标记区
- 右侧：账号、英雄、地图、模式、文件信息、收藏、标签和备注

“打开原文件位置”位于页面顶部的可见操作区。播放器和当前片段始终是页面最明显的内容。

## 4. 导航与数据连续性

主流程如下：

1. 用户在扫描目录页添加目录并开始扫描。
2. 原型显示扫描中状态，再切换到扫描完成状态。
3. 用户进入素材库，使用搜索、筛选和账号 / 对局分组浏览素材。
4. 用户点击素材卡片进入对应片段的预览页。
5. 用户返回素材库时，原型表现为保留原对局、筛选条件和滚动位置。

Figma 原型使用静态示例数据模拟数据连续性，不连接真实文件系统、数据库或视频播放能力。

## 5. 原型交互

### 5.1 扫描页

- 点击“添加目录”展示新增目录状态。
- 点击“开始扫描”进入扫描进度状态。
- 扫描完成后显示统计摘要和进入素材库的操作。

### 5.2 素材库

- 搜索框和筛选控件展示聚焦、展开和已选状态。
- 账号与对局分组可展开 / 收起。
- 收藏按钮可切换状态。
- 点击素材卡片进入预览页。

### 5.3 素材预览

- 左侧片段列表可切换当前视频。
- 播放按钮、播放进度和时间轴拖动使用模拟状态。
- 点击时间轴可打开“添加事件标记”浮层。
- 标签、备注和收藏展示编辑后的状态。
- “打开原文件位置”展示确认反馈。

视频播放、文件扫描和打开原位置均为原型状态演示，不执行真实系统操作。事件标记在首版中仅验证 UI 与交互；真实持久化能力需要在后续实现规格中单独定义数据模型与后端接口。

## 6. 状态与错误处理

首版将以下状态制作成组件变体或局部状态画板，不扩展为独立完整页面：

- 扫描中
- 扫描完成
- 扫描失败
- 素材加载中
- 素材库为空
- 搜索或筛选无结果
- 文件缺失
- 视频不可播放
- 标签或备注保存反馈

每个错误状态同时提供原因说明和可执行的恢复操作。原型不使用只依赖颜色的状态表达。

## 8. 响应式说明

首版高保真原型聚焦 1440×900 桌面窗口，不制作完整移动端页面。

Figma 中附加以下布局说明，供后续 React 实现使用：

- 1320px 以下：左侧导航收缩，右侧元数据区可变为抽屉。
- 920px 以下：主导航变为覆盖式面板，素材卡片减少列数。
- 760px 为当前应用预期的最小可操作宽度，关键操作不得不可达。

所有主要布局使用 Auto Layout 和约束组织，以便后续适配而不依赖绝对位置重建。

## 9. 与现有代码的映射

- 应用框架：`App.tsx`
- 左侧导航与扫描状态：`SourceSidebar.tsx`
- 搜索与筛选：`Toolbar.tsx`
- 账号、对局和素材卡片：`ClipGrid.tsx`
- 素材预览、标签与备注：`DetailPanel.tsx`
- 视觉令牌与响应式规则：`App.css`

Figma 原型不要求当前代码立即支持所有演示交互。后续实现计划需要区分纯视觉重构、已有业务能力接入和事件标记等新增能力。

## 10. 验收标准

- 三个核心页面视觉统一并遵循“电影兵器库”方向。
- 视频缩略图和播放器始终是最高视觉权重内容。
- 黑红视觉清晰、克制，不演变为大面积高饱和红色界面。
- “扫描 → 浏览 → 预览”主流程可点击演示。
- 搜索、筛选、分组、收藏、播放状态、事件标记、标签和备注存在可验证的交互状态。
- 无占位文案、无明显裁切、重叠或不可读内容。
- 关键状态不只依赖颜色表达。
- 组件、变量、Auto Layout 和页面命名结构清晰，可供后续 React 重构参考。
- 原型中的新增能力与现有能力边界有明确说明。

## 11. 非目标

- 本阶段不修改 React、Rust、SQLite 或 Tauri 配置。
- 不实现真实视频播放、目录扫描或文件操作。
- 不在 Figma 阶段定义事件标记的持久化数据模型。
- 不制作移动端应用界面。
- 不进行无畏契约官方客户端的像素级复制。
