# 无畏时刻管理器：电影感曜石响应式 UI 设计

日期：2026-07-12

## 目标

将现有界面从常见的红黑电竞仪表盘重做为具有电影感、空间层次和克制动效的桌面媒体管理器，同时保证 Tauri 窗口不处于全屏或最大化状态时仍可顺畅使用。

本次改造必须满足以下结果：

- 在 760px 至宽屏窗口范围内保持可操作，不出现核心内容被三栏挤压、横向溢出或操作入口不可达。
- 视觉风格与当前版本有明显差异，而不是仅替换配色、圆角或阴影。
- 使用克制、连续、尊重系统设置的动效增强层级和反馈，不使用高频故障闪烁或干扰阅读的装饰动画。
- 保留当前扫描、筛选、搜索、排序、账号与对局分组、收藏、标签、备注、文件恢复、预览和原位置操作能力。
- 不恢复已移除的击杀事件时间线。

## 视觉方向

采用“电影感曜石”方向：

- 背景以接近黑色的曜石色为主，通过大面积低饱和紫、玫红和青绿光晕建立景深。
- 内容表面使用带透明度的深色材质、细边界、高光内描边和分级阴影，而不是每个区域都使用相同的实色卡片。
- 强调色用于选择状态、关键操作、媒体光晕和少量数据提示，不大面积铺满红色。
- 视频缩略图是视觉中心。缩略图比例、渐变遮罩、标题、时长和状态信息共同形成电影海报式卡片。
- 字体沿用系统字体栈以避免 Tauri 中的网络字体依赖，通过字号、字重、字间距和对比度形成层级。
- 图标采用简洁线性 SVG；不使用 emoji 作为产品图标。

### 设计令牌

通过 CSS 自定义属性定义并集中维护：

- 背景：`--canvas-0`、`--canvas-1`、`--canvas-2`
- 半透明表面：`--surface-glass`、`--surface-elevated`、`--surface-hover`
- 边界：`--stroke-subtle`、`--stroke-strong`
- 文本：`--text-primary`、`--text-secondary`、`--text-muted`
- 强调色：`--accent-violet`、`--accent-rose`、`--accent-mint`
- 状态色：成功、警告、错误、文件缺失
- 圆角、阴影、模糊、间距和动效持续时间

所有组件使用令牌而非独立硬编码颜色，保证材质和交互状态一致。

## 响应式布局

### 宽屏：1320px 及以上

- 三栏布局：约 248px 导航侧栏、弹性媒体工作区、约 360px 详情栏。
- 工作区使用自适应卡片网格，卡片最小宽度约 220px。
- 详情栏保持可见并独立滚动，选择素材时不改变主体宽度。

### 中等窗口：920px 至 1319px

- 左侧栏收缩为约 76px 的图标导航轨道，文本名称通过提示和可访问标签保留。
- 账号、来源目录和扫描详情通过弹出面板展开。
- 详情栏改为右侧悬浮抽屉，不再持续占据网格宽度。
- 工作区保持至少两列卡片；工具栏允许换行但关键操作始终位于首行。

### 紧凑窗口：760px 至 919px

- 左侧导航转为顶部菜单按钮与覆盖式抽屉。
- 详情使用覆盖式全高面板；关闭后焦点返回触发卡片。
- 卡片根据实际可用宽度显示一至两列。
- 高级筛选以折叠面板显示，活动筛选标签横向滚动或换行。
- 顶部品牌文字、非关键状态说明和次要按钮按优先级收敛。

### Tauri 窗口约束

- 默认窗口保持适合桌面的尺寸。
- `minWidth` 调整为约 760px，`minHeight` 调整为约 560px。
- 主体区域使用 `minmax(0, 1fr)`、独立滚动容器和正确的 `min-width: 0`，避免内层内容撑破窗口。

## 信息架构与组件

### 顶部命令栏

- 左侧为产品标志、名称和当前素材数量。
- 中部为搜索框；宽度不足时自动占据下一行或收缩。
- 右侧保留扫描状态和关键扫描操作。
- 顶栏使用较轻的玻璃材质，不与内容卡片争夺视觉焦点。

### 导航与来源

- “全部、今日、收藏、文件缺失”作为第一层导航。
- 账号、来源目录和扫描诊断成为第二层可展开内容。
- 当前选中项使用低亮度渐变填充、细描边和侧边光条，不使用整块高饱和红色。
- 扫描进度使用单一连续进度动画，失败与缺失状态保持清晰文字说明。

### 工作区头部与筛选

- 标题、结果数量、排序和筛选操作组成可换行的紧凑区域。
- 活动筛选使用可移除的胶囊标签。
- 高级筛选可折叠，并在紧凑窗口中改为纵向表单。
- 筛选变化保留 React transition，视觉上使用轻微淡入和位移反馈。

### 媒体工作区

- 保留账号和对局分组，但减少重复表头，将账号身份与对局结果整理为轻量分隔标题。
- 每个对局可包含一个宽幅焦点条和常规卡片网格；当数据不足时直接使用一致网格，不制造空白英雄区。
- 卡片显示缩略图、标题、英雄、地图、时长、收藏与文件状态；次要数据在悬停、聚焦或详情中呈现。
- 缺少缩略图时生成与当前色调一致的抽象渐变封面，而不是空白占位块。
- 选中状态通过共享光环、边框和轻微缩放表达，不能仅依靠颜色。

### 详情抽屉

- 视频预览占据首屏最明显区域。
- 对局摘要采用四个紧凑数据单元。
- 文件缺失恢复操作紧邻预览，错误原因和可执行动作同时可见。
- 标签、备注和元数据按使用频率排序；文件元数据保持折叠。
- 不展示击杀事件时间线。

## 动效系统

引入 `motion`，通过 `motion/react` 实现需要布局感知或退出状态的动画；简单颜色和阴影变化继续使用 CSS transition。

### 动效类型

- 应用进入：顶栏、导航、工作区以短距离淡入，整体完成时间控制在约 450ms 内。
- 卡片列表：仅首批可见卡片进行 25–40ms 间隔的轻量错峰进入；后续筛选不重复夸张入场。
- 卡片交互：悬停上移约 3–5px、缩略图轻微放大、光晕增强；键盘聚焦得到等价反馈。
- 选择变化：选中光环与详情内容交叉淡入，避免整个页面重新闪烁。
- 抽屉：使用阻尼弹簧完成侧滑和背景遮罩过渡；关闭时保留退出动画。
- 反馈：扫描状态、收藏和标签操作使用短促的透明度或缩放反馈。
- 环境光：背景光晕只做缓慢、低振幅的漂移，且在紧凑窗口或低性能偏好下静止。

### 可访问性与性能

- 使用 Motion 的 reduced-motion 支持，并保留 CSS `prefers-reduced-motion` 兜底；系统要求减少动态效果时关闭位移、缩放和持续光晕。
- 动画优先使用 `transform` 和 `opacity`，避免频繁驱动布局。
- 不对长列表全部执行持续动画。
- 所有覆盖层保留 Escape 关闭、焦点限制、焦点恢复和背景不可交互行为。

## 技术方案

- 保留 React 19、TypeScript、Vite 和 Tauri 2 架构。
- 新增 `motion` 作为唯一必要的视觉交互依赖。
- 不引入完整主题 UI 库，以避免默认组件外观削弱定制视觉。
- 现有状态、后端调用和业务数据模型保持不变；视觉组件通过现有 props 接口消费数据。
- 将过大的样式按令牌、布局、组件和响应式规则组织；必要时将纯视觉壳组件拆出，但不进行无关业务重构。
- 继续使用现有媒体查询状态判断抽屉行为，断点与 CSS 保持单一来源或通过常量同步。

## 状态与错误处理

- 加载状态使用与最终卡片结构一致的骨架屏，避免布局跳动。
- 空结果明确区分“素材库为空”和“筛选后无结果”，并提供扫描或清除筛选操作。
- 扫描失败、素材列表失败、媒体不可播放、文件缺失和编辑失败保留独立文案及可恢复动作。
- 响应式切换时保留当前筛选和选中素材；如果面板从内嵌变为覆盖式，确保不可见媒体暂停。
- 不因视觉动画延迟实际数据写入或错误显示。

## 测试与验收

### 自动化验证

- 更新响应式布局测试，覆盖宽屏、中等和紧凑三种模式的组件可达性与抽屉行为。
- 保留并运行所有过滤、扫描摘要、详情、标签、文件状态和后端 API 测试。
- 为 reduced-motion 分支、动效包装后的点击行为和键盘关闭行为增加测试或纯函数验证。
- 运行 `npm test`、`npm run build` 和 `git diff --check`。

### 视觉与运行时验收

- 在约 760×560、900×700、1280×820 和宽屏尺寸检查无横向溢出、内容遮挡或不可达按钮。
- 启动 Tauri 桌面开发版，验证真实窗口缩放、抽屉、视频预览和滚动区域。
- 验证 reduced-motion 模式下内容可用且没有持续装饰动画。
- 检查加载、空库、无筛选结果、缺失文件、扫描中和扫描失败画面。

## 非目标

- 不修改 Rust 扫描器、数据库或元数据解析逻辑。
- 不新增在线账户、云同步或视频编辑能力。
- 不恢复击杀事件时间线。
- 不追求与 Valorant 官方客户端的像素级复制。
