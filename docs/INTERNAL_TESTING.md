# 小范围测试指南（受控内部 Alpha）

本文用于组织瓦刻的首轮小范围测试。当前测试目标是尽早发现数据安全、扫描兼容性和桌面运行问题，不是公开发布或社区分发。

> [!WARNING]
> 截至 2026-07-20，未签名 RC 只允许在项目负责人或同一法律主体控制的设备上验证。不得把安装器、FFmpeg 二进制、数据库、日志或用户素材上传到 GitHub Release、Actions artifact、网盘或群聊。主体外测试需等待公开发布阻断项关闭。

## 测试通道

### A. 浏览器界面预览

- 使用仓库内的合成 mock 数据。
- 可验证素材库、搜索筛选、扫描交互、标签、详情和批量整理界面。
- 不访问真实 ACLOS 目录，不验证真实媒体播放、系统目录选择、导出或安装器行为。

```powershell
npm ci
npm run dev
```

打开 `http://localhost:1420`。

### B. 桌面源码运行

- 只允许项目内部人员在受控 Windows 设备上执行。
- 从干净 commit 使用锁定依赖构建；记录 commit 与环境。
- 未提供受审 FFmpeg 时，缩略图会降级，不应临时加入来源不明的二进制。

```powershell
npm ci
npm run tauri -- dev
```

### C. 未签名内部 RC

- 只能由发布负责人按 [Windows 发布说明](./RELEASE.md)生成。
- 构建必须绑定干净 commit、内部 release-readiness 证据、安装器 SHA-256 和 `NotSigned` 状态。
- Windows SmartScreen 或信誉提示属于预期现象，但不能因此指导测试者关闭系统安全功能。
- 当前 RC 不得提供给朋友、社区用户或任何主体外测试者。

## 开始前

发布负责人为每个测试构建填写：

| 字段 | 记录 |
| --- | --- |
| 测试批次 ID | 例如 `alpha-internal-001` |
| Git commit | 完整 40 位 SHA |
| 工作区 | `git status --short` 必须为空 |
| 运行方式 | 浏览器预览 / 桌面源码 / 内部 RC |
| Windows | 版本、build、x64 |
| WebView2 | 版本或“缺失” |
| 安装器 | 文件名、大小、SHA-256、签名状态；源码运行填“不适用” |
| 测试数据 | 合成数据 / 复制出的可丢弃目录 / 真实只读扫描 |
| FFmpeg | 缺失降级 / 受审内部资源及其 SHA-256 |
| 游戏素材 | 清单 SHA-256、集合指纹、负责人声明记录 ID、人工审阅状态与本次操作假设 |

必须同时满足：

- 已备份应用数据目录；数据库恢复步骤见[数据库恢复指南](./DATABASE_RECOVERY.md)。
- 永久删除测试只使用专门复制出的可丢弃视频，绝不使用唯一素材。
- 测试路径、账号名、OpenID、对局 ID 和备注可以脱敏后再记录。
- `npm run assets:verify` 已确认构建中的 42 张游戏图片与固定清单逐字节一致。负责人已声明取得授权，但测试通道、地区、参与主体、有效期和展示操作尚未与授权原件完成人工核对；当前只允许负责人或同一法律主体控制设备上的本地验证，不得向外发送构建、截图或素材。状态见[负责人声明记录](../release/approvals/game-content-rights.json)。

## 首轮测试矩阵

| ID | 场景 | 最低通过标准 |
| --- | --- | --- |
| T01 | 首次启动与空库 | 窗口正常显示；默认目录不存在时给出可理解提示，不崩溃 |
| T02 | 默认与手动来源 | 可发现或添加目录；不可访问目录以警告结束，不误删历史索引 |
| T03 | 多来源扫描 | 进度、取消、完成/部分完成/失败终态明确；重启后状态可恢复 |
| T04 | 中文、长路径和多磁盘 | 可扫描可访问路径；离线磁盘被标记而不是卡死 |
| T05 | 账号与对局归组 | 合成/脱敏样本按稳定身份归组；来源间不会错误合并 |
| T06 | 搜索与筛选 | 账号、英雄、地图、模式、日期、类型、标签和状态组合结果正确 |
| T07 | 预览与事件时间线 | 可播放素材支持 seek；缺失或不可播放素材给出明确降级 |
| T08 | 收藏、标签、备注 | 重启后仍存在；批量操作只影响选中素材 |
| T09 | 回收与恢复 | 移入回收站不修改原视频；恢复后索引状态正确 |
| T10 | 永久删除（复制素材） | 再次确认后只删除目标副本；文件被替换或磁盘离线时安全拒绝 |
| T11 | 大库与窗口缩放 | 1k/10k 数据分页保持响应；760×560、100%/150%/200% 缩放可用 |
| T12 | 重启、第二实例与异常恢复 | 第二实例交接正常；扫描或删除中断后不会静默损坏数据 |

内部 RC 另需按[发布清单](./WINDOWS_RELEASE_CHECKLIST.md)覆盖 WebView2 已安装、缺失在线、缺失离线、重装、升级、禁止降级和卸载数据保留。

## 立即停止测试的情况

发现下列任一情况后停止使用该构建、保留现场并按 P0 报告：

- 未经“回收站 → 永久删除 → 再次确认”流程就修改、移动、重命名或删除原视频。
- 删除了未选中文件，或文件身份变化后仍继续删除。
- 数据库损坏、来源/标签/备注不可恢复，或升级后出现大面积错误归组。
- 应用持续崩溃、无法退出、出现无法解释的出站连接，或占用资源失控。
- 安装/卸载影响了用户原视频或其他应用数据。

## 反馈分级

- **P0 — 停止测试**：数据丢失、越权文件操作、安全/隐私泄露、安装器破坏系统。
- **P1 — 阻断批次**：稳定崩溃、无法启动、主要扫描/预览链路不可用、数据库无法恢复。
- **P2 — 应修复**：功能错误、有明确绕行方式的兼容性或性能问题。
- **P3 — 改进项**：文案、视觉、轻微交互或建议。

使用 [测试记录表](https://github.com/2424521842/valoframe/issues/new?template=beta_feedback.yml)汇总一次完整测试；单个可复现缺陷使用 [Bug 表单](https://github.com/2424521842/valoframe/issues/new?template=bug_report.yml)。P0 或安全问题不要先创建公开 Issue，按 [SECURITY.md](../SECURITY.md)私下报告。

## 脱敏规则

不要上传：

- 原始视频、WonderfulDb、LevelDB、应用 SQLite、`-wal`/`-shm` 或数据库备份；
- 未经审阅的完整日志或诊断目录；
- 用户目录、磁盘卷标、真实玩家名、OpenID、账号/对局 ID、备注和原始 JSON；
- 包含好友列表、聊天、桌面通知或其他个人信息的截图。

只提供最小复现片段。路径统一替换为 `C:\Users\Tester\...`，身份统一替换为 `FixtureAlpha#0001`，稳定 ID 使用明显的合成值。上传前由报告人再次预览全部附件。

## 退出标准

首轮内部 Alpha 结束需要：

- 零个未关闭的 P0，且没有无法解释的数据损坏或越权文件操作；
- P1 均有修复版本或明确阻断结论；
- 每条反馈都能关联测试批次、commit 和运行方式；
- 代表性 Windows 环境与测试矩阵有可审阅记录；
- 公开发布预检仍保持 fail closed，内部证据没有被误写成公开批准。

主体外邀请测试只有在第三方/FFmpeg 合规、游戏素材对主体外测试及相应安装包渠道的权利、品牌身份、签名、干净 VM、隐私披露与数据安全证据全部完成后才能开始。当前只有负责人“已取得授权”的声明；受控内部测试与 Windows 内部测试包是仓库操作假设，仍待对照授权原件确认。
