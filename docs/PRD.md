# PRD：瓦刻（VALOFRAME）

## 1. 产品定位

瓦刻（VALOFRAME）是一个面向无畏契约国服高光素材的本地桌面索引工具。它从本机 ACLOS 目录读取视频和元数据，把多个来源、账号与对局汇总到统一素材库，提供搜索、筛选、预览和整理能力。

应用扫描和日常整理默认只读访问 ACLOS 原始目录；收藏、标签、备注、回收状态和扫描索引只写入应用自己的 SQLite。唯一写入例外是用户在应用回收站中二次确认“永久删除视频”，此时删除所选本地视频。

## 2. 当前用户场景

- 自动发现默认 ACLOS 高光目录，也可手动添加来源或执行全电脑发现。
- 一次扫描多个 `wonderfulVideos*` 或自定义目录，并持续查看进度或取消任务。
- 按稳定账号和对局浏览大量素材，搜索、筛选、排序并查看全库聚合项。
- 选择素材后按需加载完整详情、事件和用户自定义标签，在应用内预览视频。
- 对缺少源封面的素材后台生成并缓存缩略图；生成器不可用时继续使用稳定回退图。
- 按三杀、四杀、五杀、六杀时刻、击杀集锦和死亡时刻筛选视频；单条或批量管理收藏、自定义标签和回收状态，为素材保存备注；回收站支持仅移除索引或永久删除本地视频。
- 通过系统文件管理器定位原文件，继续使用播放器或剪辑工具处理。

## 3. 数据与安全边界

### 3.1 原始数据只读

- 扫描器只读取 ACLOS 目录、视频、封面和元数据，不向源目录写入内容。
- 回收状态是应用索引中的管理状态，本身不删除磁盘上的原视频。
- 永久删除仅能从回收站发起，必须经过不可撤销确认；后端先持久化不可静默改写的删除意图，再以 Windows 文件/卷身份和受限句柄校验并删除同一对象，最后原子移除意图与索引。崩溃或文件占用时启动恢复继续收敛；来源离线、目标替换或路径不安全时保留索引并明确阻断。
- 不读取游戏进程、游戏内存或反作弊数据，不实时录制，也不上传素材或索引。

### 3.2 WonderfulDb

- 只读枚举 `%APPDATA%\ACLOS\WonderfulDb` 的账号文件。
- AES 解密和完整 JSON 文档解析只在进程内存中进行；不回写密文，也不在 WonderfulDb 或素材目录生成独立明文副本。
- 应用 SQLite 会保存归一化后的字段及必要的事件、快照 JSON，用于本地索引和详情展示。
- 单个账号文件读取、解密或解析失败只产生警告，不阻断其他账号和 MP4 入库。

## 4. 已实现范围

### 4.1 来源与扫描编排

- 默认发现 `AppData\ACLOS\aclos-highlight` 下的 `wonderfulVideos*`，支持手动目录和 Windows 固定磁盘发现。
- 后端 `scan_roots` 一次接收多个根目录，规范化并去重路径，在同一批次中统一读取元数据和汇总结果。
- 同一时间只允许一个扫描任务；任务具有稳定 ID、阶段进度、终态和取消信号。
- 单个来源或元数据文件失败会记录错误并继续；不可访问来源不会导致历史素材被误标为丢失。
- MP4 可位于来源根目录或对局子目录。文件重新出现时恢复为可用，未再次发现的历史文件保留记录并标记为 `missing`。
- `list_sources` 直接读取 `source_dirs`，返回真实路径、名称、状态、错误和素材数量；零素材来源也可展示。

### 4.2 四路元数据

扫描器合并以下四路数据，缺失或损坏时继续降级：

| 来源 | 主要内容 | 角色 |
| --- | --- | --- |
| WonderfulDb | 官方 match/video 身份、标题、分类、分段和视频内事件 | 最高优先级 |
| `videoExportTmp/config-*.json` | 玩家、地图、模式、KDA 等导出字段 | 文件级弱解析 |
| `highlight.log` | 玩家、地图、模式、英雄、比分、战斗分和事件 | 对局级补全 |
| Local Storage LevelDB | battle/match ID、KDA、日期和英雄头像 | 历史回退 |

最终字段优先级为 `WonderfulDb > 导出 JSON > highlight.log > LevelDB > 文件名/路径推断`；较低优先级只补空或修正旧的推断值。

账号身份优先使用 `matchAccountId/openid` 等稳定 ID，玩家名只用于展示和搜索。改名不会拆分同一账号，相同昵称也不会合并不同账号。

### 4.3 大素材库浏览

- 生产前端通过 `list_clip_page` 获取轻量摘要，默认每页 50 条；筛选、排序和搜索在后端执行并返回总数与下一页游标。
- “全选全部结果”会在用户明确触发后以最大 200 条/页补齐当前筛选结果，再一次性建立完整选择；普通浏览仍只增量加载当前页。
- 摘要包含卡片、分组、稳定账号、真实来源、战斗分、收藏/状态和轻量标签 ID，不携带备注、OCR、原始 JSON 或完整事件。
- `get_library_facets` 独立聚合全库账号、英雄、模式等筛选项与计数，不依赖前端已加载页。
- 选择素材后才调用 `get_clip_detail` 加载完整 Clip、事件与标签；前端用请求令牌隔离快速切换产生的旧响应，并缓存少量最近详情。
- 素材列表按对局组使用真实虚拟化和增量加载；单个对局超过 48 条时继续在同一滚动容器内按视觉行二级虚拟化。

### 4.4 整理与交互

- 支持收藏、自定义标签、备注及回收状态，扫描更新不会覆盖这些用户数据；扫描分类不会写入自定义标签。
- 批量收藏、标签和回收操作由单个后端命令在事务中完成，不逐条往返调用。
- 收藏、标签或回收操作若影响当前筛选条件，前端只执行一次受控分页刷新。
- 备注草稿与媒体加载分离，保存备注不会重置视频播放位置。
- 素材卡片中的复选框、收藏和预览入口具有独立键盘行为。
- 素材卡片优先展示 WonderfulDb 提供的单视频 `roundScore`；缺失时，仅可用本地官方日志按 GameID 分局、按 OpenID 绑定同账号后，经唯一结算总分、可用玩家身份和连续回合共同确认的累计战斗分差精确恢复。日志尾部未出现的回合不推算；无法唯一验证的计分视频显示“官方未同步”，不计分类型不显示评分；禁止回退到对局级 `combatScore` 或生成模拟评分。

### 4.5 媒体协议

- 视频通过应用自定义协议按数据库 ID 解析路径，普通请求使用只读数据库连接。
- Range 响应单段最多为 1 MiB；即使客户端未提供 Range，大文件也只返回有界分段，不把整段视频读入内存。
- 卡片优先使用源目录中已存在的 `cover-*.jpeg`；存在受控生成器时，缺失封面由 SQLite 持久队列和单 worker 生成应用缓存缩略图。
- 生成缓存按视频路径、大小、修改时间和输出版本指纹失效；缓存达到 512 MiB 后清理到 450 MiB，源目录始终只读。
- 生成器仅从打包的 `bin/ffmpeg(.exe)` 或绝对路径 `VHM_FFMPEG_PATH` 解析，不搜索系统 `PATH`；不可用时全局降级为回退图，不产生逐素材失败风暴。
- ready 事件只更新当前分页摘要、详情缓存和视频 poster，不重载列表或重置播放位置。

## 5. 质量门槛

仓库只使用 npm 和 `package-lock.json`。本地与 CI 的基础验证为：

```powershell
npm ci
npm test
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets --all-features -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked --all-targets --all-features
```

- 前端测试包含纯函数/契约测试和 React 真实交互测试，覆盖分页、虚拟化、键盘、备注保存、快速切换和批量操作。
- Rust 测试覆盖数据库迁移与查询、四路元数据、扫描编排、取消、媒体 Range 和批量事务；真实 ACLOS 回归保持为手工、忽略测试，不能读取用户素材作为默认 CI 前提。
- 数据库启动必须拒绝未来 schema，迁移前后执行健康检查，旧库升级前创建经验证的 WAL 安全备份，并用单事务提交 schema 与版本号；失败时提供可见恢复入口而非静默退出。
- 应用只允许一个实例操作同一数据与缓存；重复启动恢复、显示并聚焦现有主窗口，不接收外部文件参数。
- `.github/workflows/ci.yml` 在 Ubuntu 运行 `npm ci`、前端测试和构建，在 Windows 运行 Rust 格式、严格 Clippy 和完整测试。
